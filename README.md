# Data Analytics REST API Service

Аналитический API-сервис обработки данных, разработанный по техническому заданию кейса от компании «E-soft».

Сервис позволяет загружать файлы CSV/Excel, хранить их в PostgreSQL, анализировать
Pandas (среднее, медиана, корреляция), очищать данные и строить графики.

## Функциональные возможности

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST  | `/upload` | Загрузка файла `.csv`/`.xlsx`/`.xls`. Сохраняется в PostgreSQL. Лимит 25 МБ. |
| GET   | `/files`  | Список всех загруженных файлов (метаданные, без байтов) |
| GET   | `/data/stats?file_id=<id>` | Среднее, медиана и корреляционная матрица (Pandas) |
| POST  | `/data/clean?file_id=<id>` | Очистка: удаление дубликатов, заполнение NaN. **Не** разрушает исходник — создаёт очищенную копию |
| GET   | `/data/plot?file_id=<id>&plot=corr\|hist\|box` | PNG-график. Типы: `corr` (тепловая карта корреляции), `hist` (гистограммы), `box` (ящики с усами) |
| POST  | `/analyze?file_id=<id>&plot=corr` | Полный анализ: статистика + график, сохраняется в БД |
| GET   | `/data/file/<id>` | Скачать содержимое файла |
| DELETE| `/data/file/<id>` | Удалить файл и связанные результаты анализа |

Все ошибки (`400`, `404`, `413`, `415`, `422`, `500`) возвращаются в формате JSON, а не HTML.

## Как это работает (принцип)

1. **`POST /upload`** — принимает файл, проверяет расширение и размер, сохраняет
   сырые байты в таблицу `uploaded_files` (столбец `LargeBinary`).
2. **`GET /data/stats`** — по `file_id` достаёт байты из БД, в `services.load_file_to_df`
   воссоздаёт `pandas.DataFrame`, затем `compute_stats` считает метрики. Результат —
   JSON, понятный клиенту.
3. **`POST /data/clean`** — читает DataFrame, убирает дубликаты и заполняет NaN,
   сериализует обратно и **сохраняет как отдельную запись** с полем
   `original_file_id` (указывает на исходник). Исходный файл не меняется.
   Это делает операцию безопасной и откатываемой.
4. **`GET /data/plot`** — строит график Matplotlib в памяти (`Agg` backend),
   отдаёт PNG. Тип выбирается параметром `plot`.
5. **`POST /analyze`** — совмещает статистику и график и записывает результат в
   таблицу `analysis_results` (вместе с PNG в `LargeBinary`).
6. **DELETE/Cascade** — при удалении файла связанные записи анализа удаляются
   автоматически (отношение `delete-orphan`).

Слой `services.py` изолирует Pandas/Matplotlib от HTTP: логику легко покрыть
тестами и переиспользовать, а `routes.py` отвечает только за парсинг запроса
и формирование ответа. Собственные исключения (`errors.py`) прокидываются в
глобальный обработчик в `__init__.py`, который единообразно возвращает JSON.

## Инструкция по развертыванию

1. Склонируйте репозиторий и установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
2. Создайте базу данных в PostgreSQL и задайте подключение через `.env`
   (см. шаблон ниже).
3. Запустите:
   ```bash
   python main.py
   ```
4. Проверьте: `http://127.0.0.1:5000/files` должен вернуть `{"count": 0, "files": []}`.

### Переменные окружения (`.env`)

Создайте файл `.env` в корне на основе шаблона:

```bash
cp .env.example .env
```

```env
DB_USER=postgres
DB_PASSWORD=ваш_пароль
DB_HOST=localhost
DB_PORT=5432
DB_NAME=esoft_analytics_api
FLASK_DEBUG=True
```

> ⚠️ `.env` не должен попадать в Git — он уже в `.gitignore`. Перед публикацией
> на GitHub убедитесь, что файл не закоммичен, и смените пароль БД, если он
> где-то засветился.

## Примеры запросов (curl)

```bash
# Загрузка файла
curl -F "file=@data.csv" http://127.0.0.1:5000/upload

# Статистика по файлу 1
curl "http://127.0.0.1:5000/data/stats?file_id=1"

# Очистка данных (создаёт очищенную копию)
curl -X POST "http://127.0.0.1:5000/data/clean?file_id=1"

# График — тепловая карта корреляции (скачать as PNG)
curl "http://127.0.0.1:5000/data/plot?file_id=1" --output plot.png

# График — гистограммы
curl "http://127.0.0.1:5000/data/plot?file_id=1&plot=hist" --output hist.png

# Полный анализ с сохранением в БД
curl -X POST "http://127.0.0.1:5000/analyze?file_id=1&plot=corr"

# Список файлов
curl http://127.0.0.1:5000/files

# Удалить файл и его анализы
curl -X DELETE http://127.0.0.1:5000/data/file/1
```

## Запуск в продакшн-режиме (Docker)

Проект готов к контейнеризации: образ собирается из `Dockerfile`, а `docker-compose.yml`
поднимает две службы — веб-приложение на gunicorn и PostgreSQL. Всё стартует одной командой:

```bash
# Собрать и запустить (create_app сам создаст таблицы при старте api)
docker-compose up --build
```

После запуска API доступен на `http://localhost:8000`.

Параметры подключения к БД берутся из `.env` (см. шаблон выше) со значениями по умолчанию:
- `DB_USER` (по умолч. postgres), `DB_PASSWORD` (по умолч. postgres), `DB_HOST` (в контейнере = `db`), `DB_PORT`, `DB_NAME`.

Остановить: `docker-compose down` (данные БД сохраняются в volume `pgdata`).
Полный сброс вместе с данными: `docker-compose down -v`.

## Запуск тестов

Проект покрыт автоматическими тестами (pytest) с in-memory SQLite — подключение
к реальному PostgreSQL для тестов не требуется.

```bash
python -m pytest -q
```

Тесты проверяют: корректные коды ответов загрузки (`201/400/413/415`), работу
CRUD (`upload`/`get`/`delete`), каскадное удаление анализов при удалении файла,
создание очищенной копии без мутации исходника, генерацию PNG всех типов
графиков, обязательность параметра `file_id`.
